For a while now I have been the accountant of my gymnastics club.

The work has two parts: booking what happened, and finding what belongs to what. Booking is quick. Finding takes time. A booking needs a receipt, a receipt belongs to a payment, and all three arrive by different routes. To find out what a credit from March was for, you compare amounts, dates and names.

I no longer wanted to do that by hand, so I built myself an AI assistant: a knowledge base that collects all the data of the club's bookkeeping, files and other data sources in one place and makes it available to an AI through an MCP ([Model Context Protocol](https://modelcontextprotocol.io)).

But let's not talk about boring accounting stuff but see how it's built.

### Two kinds of import

**Structured exports** like bookings go straight into tables. Every row has a natural key from its respective data source. Importing data twice changes nothing.

**Everything unstructured** like receipts go through a pipeline that puts them into the right place.

The first step pays off more than you would think. In a club, an invoice appears on multiple places like file storage, mail and booking receipt. The hash stays the same, so the file is stored, read and embedded only once. A separate table records every place it showed up.

### Bank reconciliation

This job needs no AI at all and still saves the most time. After every import it looks for the matching booking for each bank line, in two passes.

**QR payments first.** Their reference contains the invoice number. If reference and amount match, the pair is confirmed, even inside collective credits where the bank bundles many payments into one line.

**Then everything else.** Without a shared reference, the assistant looks for bookings with the same amount in the same direction, at most 60 days apart, and scores each pair:

```text
score = 0.6 × date proximity + 0.4 × name similarity
```

A pair is only confirmed with a score of at least 0.8 and a lead of at least 0.15 over any competing pair. That matters in a club because when four members pay the same fee in the same month, the pairs look almost identical, and picking one would be guessing. Such pairs stay candidates, and me or the AI decides.

## The data storage

Data lives in exactly two places, and neither can be reached from outside. The only way in for the AI is through the MCP tools.

**Postgres** holds everything structured: accounts, bookings, bank lines, mails, files, vectors, links, the inventory, the import log and the AI's memory. The `pgvector` and `pg_trgm` extensions cover vector and fuzzy text search, so no separate search engine is needed.

**S3** holds the original files so the postgres database is not bloated with raw files.

### Connections

The links table ties it all together. Every record can be connected to others, and the AI can follow those connections with a single tool call:

- **Bank line and booking**, found by the bank reconciliation.
- **Receipt and booking**, delivered by the accounting software or found by the AI.
- **Mail and attachment**, recorded on import.
- **File and its occurrences**, every place the same file showed up.

Each link has a source (rule, AI or me) and a status: candidate, confirmed or rejected.

## Vectorization

For the AI to search documents, every file has to become text, and every text has to become vectors.

### OCR

PDF, Word, Excel, CSV and HTML are read directly. Photos and scans go to a vision model with a narrow instruction. Large phone photos are scaled down and cut into strips first.

I deliberately left out extracting fields like amount, date or supplier. The whole text is stored, and the AI reads it when it needs something.

### Embeddings

Every text is cut into sections of about 1,500 characters, preferably at the end of a paragraph or sentence, with some overlap. A hit then points to a readable passage. Each section becomes a vector and is stored in Postgres together with the model's name, so a model switch can be detected and the old sections embedded again.

OCR and embeddings run through a EU-based provider.

### Three ways to search

**SQL** is for numbers, sums and lists: account balances, budget against actuals, open invoices, bank lines without a booking. Views for bookings, balances and the bank reconciliation spare the AI from rebuilding the logic of double-entry bookkeeping.

Letting an AI write SQL needs safeguards. Every query runs as a Postgres role that may only read and cannot see the technical tables, in a read-only transaction with a ten-second limit that is rolled back at the end:

```sql
begin;
set transaction read only;
set local statement_timeout = '10s';

select * from (
  -- the AI's query
) as result limit 500;

rollback;
```

**Keyword search** is for names, invoice numbers and IBANs. It combines Postgres' full-text index with trigrams, so typos and partial words are found too.

**Semantic search** is for topics. The question is embedded into vectors and Postgres finds the closest sections. A question about the youth camp also finds mails that only use the club's nickname for it.

### A memory

The AI forgets everything after each conversation. That's bad when information is gathered that helps understand existing data.

So there is a `knowhow` table with two tools to read and write it. The AI is told to look things up at the start of every conversation and to store anything that applies beyond the current question. Every entry can be edited in the dashboard.

Over time this grows into a reference book of the club's bookkeeping.

## The costs

The complete system maybe looks big and resource-intensive but it's actually not.

The assistant with all services and resources costs around 8-10 francs per month to run and to keep up-to-date.

I chose open-weight ai models that are right for the job and do cost a fraction of frontier models but get the job done extremely well.

Let's better not talk about how much my Claude subscription costs to actually use this assistant...

## What it gives me

The assistant does not replace me. It does not book, it does not sign, and at the audit it is still me sitting there.

But questions that used to cost an evening, it answers in minutes. And every answer points to its source: a booking, a bank line, a mail or a file I can open. An accountant should not believe anything without a receipt. The same goes for the assistant.
